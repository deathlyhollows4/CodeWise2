# Authoring interface and ownership

Every author owns a disjoint set of IDs from the amended 243-slot matrix. The original specification is preserved; current topic quotas and per-ID hidden-case requirements come from `packages/contracts/src/delivery-scope.json`. Writing a pack is not publication. The backend worker currently owns the central registry, catalogue, selected materialization and merge scripts; the judge/content worker owns shared harnesses, validators, audits and isolated reference runs. Send completed IDs and pack paths for merge; never regenerate another worker's pack. Full new formats must pass real isolated language tests before publication.

Minimum pack files follow existing `content/problems/arrays-hashing-01`: problem.json, statement.md, visible-cases.json (exactly3), private/hidden-cases.jsonl (the 191 preserved authoring IDs require at least 200 distinct valid cases; the 52 explicitly listed later IDs require exactly 60), suite-manifest.json, generator/oracle source or pinned generator module, mutation evidence, three language starter/wrapper/reference files, provenance.json and validation.json. SchemaVersion1 is the shared contract. Public DTO fields are allowlisted by `packages/judge-adapter/src/content.mjs` and runtime validated by backend contracts. Never give hidden expected outputs to a harness. `validationIdentity(pack,language)` binds immutable content/checker/harness/reference to validation evidence.

## Inputs and harness API

The three legacy scalar packs use `integer-batch-v1`, which accepts an object `{values: int[]}` and outputs one integer per case. Other packs use `manifest.harness.encoding = "json-lines-v1"`: one JSON input object per line, one JSON output per line, independent Solution instance per case. `content/authoring/harness.mjs` exports `buildFunctionHarness({method,arguments:[{name,type}],returnType})` producing Java/C++/Python wrappers. Primitive/array/matrix/string type mapping is implemented for `int`, `long`, `boolean`, `string`, `int[]`, `long[]`, `string[]`, `int[][]`, `json`; arguments are parsed in trusted wrappers rather than by learners. Starter/reference signatures must match the chosen interface. JSON structured scalar/array/matrix/graph representations use the pinned parser dependencies in the isolated distro: C++ nlohmann-json (MIT), Java Gson (Apache-2.0), Python standard json. Linux installed parser package versions and actual jar/header hashes must be captured before using these wrappers; package presence alone is not execution proof.

Input schemas support bounded safe integers/numbers, ASCII strings, booleans, null, arrays (including nested rectangular matrices), and strict objects with required fields. Explicit maximum nodes/depth/serialized bytes protect backend processing. Lossless >2^53 integer values must be decimal strings with schema-defined signed64 bounds and language-specific decode/encode helpers; the primitive long generator currently supports only JSON-safe inputs, not this lossless-string contract. Graphs use bounded vertex count plus edge pairs/adjacency lists, with schema/content oracle verifying vertex ranges and duplicate/self-edge rules. Typed `int[][]` graph edges avoid parser work for most graph tasks.

List/tree/graph **identity** and stateful operations use implemented specialized helpers beyond the primitive templates. The contracts below describe native learner types, not JSON stand-ins. Current source and native receipts must still be checked for each exact generated wrapper.

- Simple list: integer values with sequential next links; learner receives typed ListNode, not JSON.
- Identity list: `{values:[...],next:[index|null,...],heads:[index|null,...]}`; build one node per index and preserve aliases/cycles. Return node identity as index|null, never compare values.
- Tree: compact breadth-first values with null children. Build real typed nodes; node identity may use stable node IDs when required. Empty tree is null. Define trailing-null normalization before input hashing.
- Identity graph: one node object per vertex ID plus adjacency; graph clones checked for topology and separation from originals.
- Stateful class: operation sequence of constructor/method calls as one case. Trusted wrapper dispatches only pack-approved names and types, resets class between cases, and returns an output sequence. No arbitrary eval, method reflection, or browser-selected class/method names.

`structures.mjs` also supports `IdentityTree` (native root and selected original nodes) and `MultiListNode` (next/prev/child). The selected Tree17/LL22/Tries01/02 native slice passed all 12 language receipts under the recorded runtime; see `bank-validation-native-four-snapshot.json`. Stateful `CoverageSet` wrappers have trusted static/model tests, with all three isolated reference receipts passed in bank-validation-current-34-snapshot.json. General JSON arrays alone do not satisfy a native node/class interface.

## Reviewed presentation metadata

The published classification sidecar uses `content/learning-tags.json` and an independent approval in `content/learning-tags-review.json`. Every current problem ID has its current `packIdentity`, explicit `secondaryTopics` and one or more `approachTags` from the document's closed vocabulary. Empty secondary topics are appropriate for a genuinely single-topic objective. Classifications describe the supplied algorithms and materially related concepts, rather than copying the primary topic or every prerequisite.

The independent approval binds the canonical hash of the entire mapping. Missing, invalid or stale classification blocks its publication gate. This presentation layer does not change the grading manifest, inputs, wrappers, checker or reference receipt identity. A grading-content change still stales its classification through the bound `packIdentity`.

`GET /api/problems/:id/learning-metadata?version=<current-version>` returns runtime-validated classification separately from the immutable core problem snapshot. An older requested version receives a mismatch response rather than current labels for retired text. The author of a mapping does not approve their own mapping. The final API audit checks all 243 current classification responses independently of native judging.

## Checkers and independent evidence

`checkOutput` supports exact structured, ordered sequence, mathematical set, multiset and numeric tolerance. Use ordering/duplicate semantics stated in the problem. For validity/witness tasks, author a trusted reviewed checker **in the application registry**, with valid alternative and deliberately invalid test fixtures; never put executable checker code in a dynamic pack or trust one reference output. Geometry tolerances need both absolute/relative rules and boundary fixtures. Graph witnesses need content validity checks and optimum objective comparison. A not-yet-supported checker must fail closed.

Add independent brute-force oracles for small generated inputs and explicit properties for large cases. Record categories, seed/version, unique canonical hashes and structural diversity. Every expected answer must have real oracle evidence. Mutation evidence names faults actually detected, never an invented percentage. Fixture tests do not count as real learner/reference execution. Use `node scripts/validate-bank.mjs --slice` only for clearly labeled authored-slice validation; the default command requires all 243 current questions and the exact shared topic quotas. `--ids` requires `--slice`; always save the explicit selected IDs and immutable report before another run. All references execute every case in all3 languages. Runtime and content hash changes invalidate evidence.

Current slice metadata: first2 step1 traversal/reduction checkpoints; step2 first-repeat teaches membership state. Specific skills/prerequisites/rationale are authored in pack JSON. Matrix default adjacency links are provisional and must be replaced by actual authored metadata; missing planned checkpoint packs remain a reported coverage gap.

## Scoped authoring and canonical inputs

Use `hiddenCaseRequirement(id)` from `packages/contracts/src/hidden-case-requirement.mjs`; never infer policy from topic or trim a generator to its first 60 outputs. `logicalCases(def)` enforces the exact/minimum requirement after schema validation, canonical deduplication and visible-case exclusion. Keep independently certified maximum-size representatives and meaningful branch/structure diversity.

Unordered arrays use locale-independent canonical string ordering. Declare `deduplicate:true` only together with `unordered:true` when identical entries have no extra semantic effect; retain multiplicity for counts and index identities. `labelFrequencyProfile:true` is restricted to unordered integer arrays without deduplication and removes arbitrary task-label renaming from cooldown case identity. Canonicalization never mutates the actual learner input.

The legacy `node content/authoring/slice.mjs` entry point refuses to write because it formerly replaced the central catalogue. Coordinate explicit selected materialization with its current owner. Runtime execution always uses the isolated normal adapter and a current attested identity; trusted author models and syntax checks are separate evidence.
