# CodeWise2 API v2

All routes use same-origin `/api`. `GET /api/bootstrap` reuses a valid HttpOnly SameSite=Strict local session cookie and returns `csrfToken`. Every mutation sends `X-CSRF-Token`, exact matching Origin and JSON content type. Responses use runtime-validated DTOs; history collections use page envelopes. Errors are `{code,message,recoveryAction,requestId}`. Runtime schemas live in packages/contracts/src/index.ts.

GET bootstrap → `{apiVersion,appVersion,csrfToken,preferences,runner,catalogue:{published,expected:243},key:{configured,masked,status,lastChecked},platform,storagePath}`. Topic quotas and derived totals come from the runtime-validated shared `packages/contracts/src/delivery-scope.json`, applying the user-authorized scope amendment; visible examples and language pairs remain three per question.
The same machine authority contains explicit `hiddenCaseOverrides` for52 unstarted cutoff IDs, each requiring exactly60 canonical distinct hidden cases. Existing191 IDs keep the minimum200 rule and their authored larger suites. The shared Node/TypeScript policy helpers enforce these per-ID rules; assessment and validated backups require exactly63 total cases for an override ID, or at least203 for an earlier ID, plus full executed/passed accounting for independent acceptance. Submit always executes the complete actual immutable suite; the smaller target never permits a partial-suite Accepted result.
GET topics → topic array `{id,name,quota,count,independent,assisted}`. GET problems?topic=&q= → public published problem array. GET problems/:id → PublicProblem.
GET drafts/:problem/:language → `{code,revision,updatedAt}`. PUT same with `{code,revision}`; stale revision 409.
POST jobs → JobRequest; GET jobs/:id → immutable job `{id,...request,status,result,createdAt,finishedAt}`. GET jobs?problemId= → history. POST jobs/:id/cancel → job.
GET recommendation?topic=&language= → `{problemId|null,mode,rationale,ruleVersion,requestedStep}`. GET progress → `{independent,assisted,evidence,reviewQueue}`.
POST tutor → TutorRequest, returns saved generation. GET tutor/:id → saved generation. GET tutor/:id/events?after=0 → SSE persisted events with numeric IDs, chunk/status JSON. POST tutor/:id/cancel.
GET library?q=&language=&problemId=&status=&bookmarked= → saved outputs. GET library/:id → lesson generation. PATCH library/:id `{bookmarked?,notes?,tags?}`. DELETE library/:id `{confirmation:'DELETE'}`. GET library/:id/export?format=markdown|json.
GET settings → `{preferences,key,models,usage}`. PUT settings → partial Preferences. POST settings/key/test `{key?:string}` → connectivity result/model IDs, never key. PUT settings/key `{key,replace?:boolean}` saves encrypted even offline. DELETE settings/key `{confirmation:'REMOVE'}`. POST settings/tutor-test `{consent:true}` is explicitly billable.
GET data/export → versioned JSON backup excluding secrets. POST data/import/preview `{backup}` validates without writing → `{counts,token}`. POST data/import `{backup,token,confirmation:'RESTORE'}` atomic replacement after local safety backup. POST data/reset `{confirmation:'RESET PROGRESS'}` resets progress only.
GET sources → bundle provenance. GET health → sanitized readiness. Unknown catalogue IDs 404. Unready runner jobs record infrastructure_error; no host execution fallback. Published count reflects actual audited catalogue.

Assessment: GET assessment returns strict schemaVersion2/ruleVersion `assessment-1` state, with selected questions/reasons, observed outcomes, independently demonstrated skills and explicitly unassessed skills. POST assessment/start `{experience:'beginner'|'some'|'comfortable',language}` starts a conservative adaptive6–10-question session using actual eligible catalogue tasks; experience selects an early path-local starting depth. Status `unavailable` honestly indicates insufficient content. POST assessment/next consumes at most one full eligible result for the current immutable session/question/version/language selection, then chooses an incremental, checkpoint/remediation or breadth probe. Run, review, stale-session, other-language, incomplete and starter-only failure results never count as independent demonstrations. POST assessment/stop consumes an eligible finished current result without choosing another question and preserves unknown/unassessed skills. Legacy assessment history is preserved as explicitly restartable state without inventing mastery. POST learning/select `{problemId,mode:'manual'|'review'}` records navigation intent without awarding progress. JobRequest.review identifies explicit review submissions.

GET library and GET jobs return `{items,nextCursor,total,pageSize}` projected summaries, default30/max100 rows, ordered descending by `(createdAt,id)`. Opaque cursors are signed and bound to the route/filter query; invalid, stale or changed-query cursors return400 `CURSOR_INVALID`. Optional filters must be omitted when unset. Library q searches the complete stored visible answer, learner code, title, prompt and notes, never private inference context; previews/excerpts are bounded400 characters. Date `from`/`to` filters use inclusive UTC calendar days. Summaries omit full Markdown/code/notes/private context. GET library/:id and GET jobs/:id retain full selected detail; full version history remains accessible by paged `threadId` query, and exports preserve complete bodies. Restore and full-history reset invalidate prior cursors.

Custom job success status `executed` means no trusted expected answer was available; counts.unverified reports executed cases without acceptance. It never awards learning evidence.

Tutor streams coalesce text into at most8192 UTF-16 characters per durable batch, flushing short buffers after100ms and on completion/cancellation. Only committed event payloads broadcast. Latest128 events per generation are retained; the full saved answer remains authoritative. An initial cursor (`after=0`), expired cursor, or cursor beyond the current sequence receives `{type:'snapshot',seq,text,status}`. Clients replace accumulated text with the snapshot, then append following chunk events. Current cursors replay only later committed events. Reopening/reconnecting never invokes inference.

Complete compact backups are limited to64MiB of UTF-8 JSON. Export preflights schema and size, preview/restore enforce the same size after validation, and the import HTTP body allows4KiB additional wrapper metadata. Oversize export returns413 `BACKUP_TOO_LARGE` without emitting a partial backup; oversize request returns413 `REQUEST_TOO_LARGE`. Existing profile data stays intact. This format buffers JSON within the bound; it does not compress or silently prune history.

Learning rule `learning-4` retains learning-3's prerequisite-bridge purpose as `pendingMode:'next_step'|'same_step_checkpoint'`. Durable pending metadata stores `resumeMode`, original topic/step/source and teacher IDs; an old accepted source or teacher cannot clear that original challenge. Teacher completion/reopen/refresh returns to the same requested purpose. Legacy pending records default to next-step behavior. Recommendations may expose `practiceSkills`: for an unseen explicitly linked same-step checkpoint after an accepted assisted source, a prerequisite taught/tested by BOTH tasks is ready to practise. This grants access only; no known skill, independent evidence or advancement is added. All external prerequisites still require independently demonstrated teachers, and next-step eligibility never uses practice access. A subsequent independently accepted checkpoint creates ordinary independent evidence.

Same-step selection is restricted to the source's explicit checkpoint links; it cannot substitute an unrelated task. Teacher search follows only explicit remedial links, recursively considering unproven teacher prerequisites, with cycle/visited guards and bounds of8 edges/128 visits/128 queued nodes. It chooses only an unseen/unexposed teacher whose prerequisites are already independently known. Pending checkpoint intent is cleared only by a newly advancement-eligible accepted related checkpoint at that exact step; repeated-language/duplicate evidence and unrelated manual solves cannot clear it. A newly assisted checkpoint recomputes same-step practice, never advancement. Exhausted already-solved/exposed related peers yield consolidation with an exhaustion explanation.

Jobs/evidence optionally expose `meaningfulConceptualAttempt`. Learning-4 excludes wrong-answer starter-only failures from the distinct failed-attempt remediation count. The comparison uses that language's immutable captured starter and the limited versioned source-comment heuristic; it is not semantic equivalence or proof that edited code is a different algorithm. Verdicts/jobs/history are preserved. Actual accepted judge evidence is never suppressed, including a coincidentally accepted unchanged starter. Legacy unflagged failures are classified for recommendation replay only when their immutable job snapshot exists; historic evidence is not rewritten. Automatic explanations skip known starter-only failures, while explicit user-requested tutor actions remain available.

Review schedule `review-calendar-1` adds1/3/7/14/30 calendar days in the current saved Settings timezone, preserving local wall time. DST gaps advance to the corresponding later time; repeated times use the earlier occurrence. `scheduledReviews`/`reviewQueue` items expose `timezone` and `scheduleRuleVersion`, with `dueAt` still an ISO UTC instant. Changing Settings timezone intentionally recomputes existing due instants from unchanged UTC evidence; the timezone is not captured per attempt. Scheduling never advances or clears a harder pending challenge.

Execution dispatch binds an opaque64-hex `executionIdentity` to each immutable job. The backend captures it from the trusted adapter using the cached public problem snapshot and selected language before queue insertion; capture/public-version mismatch returns409 `CONTENT_IDENTITY_CHANGED` without creating a job. An ordinary adapter lacking identity capture returns503 `CONTENT_BINDING_UNAVAILABLE`. Dispatch supplies this identity for the adapter's private snapshot comparison; mismatch executes no cases and creates no learning evidence. This hash contains no private suite payload. Legacy saved jobs may omit it, but ordinary execution cannot dispatch such jobs.

Jobs remain `queued` until actual authenticated runner callbacks indicate `compiling` or `running`; invalid callbacks and callbacks after terminal status/cancellation are ignored. Each grading phase may compile a fresh isolated invocation, so an actual hidden-phase compile can follow a visible-phase run. Backend fixture regressions establish persistence/dispatch policy; actual broker protocol verification is recorded separately.

Tutor prompt version `tutor-4` captures up to32 relevant independently accepted skill IDs, each with up to3 supporting evidence IDs and demonstrated languages. Assisted acceptance, failures and unknown skills never become independent knowledge from this context. An explicit continuation from a canceled/interrupted/failed parent includes its unchanged saved partial suffix (at most12000 characters) and lifecycle label. Reopen/restore never calls inference; explicit regeneration/continuation prepares a new immutable context from saved public history. Action guidance requests selected-language explanations, concrete visible examples before abstraction, evidence-limited error diagnosis, useful invariant/recurrence reasoning and justified complexity; headings/code fences/tables are used when helpful without forcing a long hint template. This is a tested prompt contract, not live model-output quality evidence.

Exact `contextMessages` are server-only SQLite data. All public generation responses, library JSON exports and normal backups omit them, preserving saved visible text, user prompt/code, model/output-limit/prompt-version metadata and original context hash. A restored answer therefore retains history/hash but does not recover private inference messages; only an explicit new request recomputes them. Read-only `getVerifiedReference` verifies current cached public snapshot/private identity/selected-language historical full receipt before an explicit `solution` request can include code. Optional `referenceProvenance` contains language/version/validation identity/verification time/runtime identity and basis `historical-full-reference-execution`, never code. Historical reference validation does not prove current runner health or validate generated code: generation verification remains `not-run`. Unavailable/mismatched references are omitted. Assistance begins with the first committed visible answer chunk. Preparing a private reference before a provider failure grants no assistance if the learner receives no visible help.

Learning Preferences add `focusTopic` (authorized topic ID or null), `reviewPreference` (`balanced`, `new-first`, `review-first`) and `defaultHintDepth` (`nudge`, `concept`, `steps`). Old profiles/backups default to null/balanced/concept without changing evidence. Invalid values reject before saving. Saved focus supplies the recommendation path only without an explicit topic override or preserved pending challenge. Recommendation `practicePresentation` includes `ruleVersion:'learning-settings-1'`, preference, `first:'review'|'challenge'`, dueReviews and reason. Review-first prioritizes presentation when any review is due; balanced does so with at least3 due; new-first shows the challenge first. The original recommendation/pending challenge is preserved. Hint depth is captured in immutable hint messages and optional generation `hintDepth`, stays within512 output tokens, and cannot request a full solution.

Ordinary API runner readiness is false when trusted content capture is absent even if the isolated sandbox has an attested configuration. The reason distinguishes sandbox setup from normal job dispatch availability. No runner protocol or control state is modified by this availability gate.

## Separately versioned learning classifications

`GET /api/problems/:id/learning-metadata?version=EXPECTED_VERSION` returns the current classification DTO: `schemaVersion`, `metadataVersion` (canonical approved mapping hash), `problemVersion`, `problemId`, `contentIdentity`, `primaryTopic`, `secondaryTopics`, `approachTags`, and `rationale`. The requested version is optional for current-catalogue views; callers showing historical material must provide it, and mismatch is409 rather than silently attaching current labels to retired content. The core public problem/immutable grading snapshot is unchanged. Reading classifications never updates evidence or invokes inference.

Runtime delivery uses `content/learning-tags.json` and `content/learning-tags-review.json`. The strict mapping contains exactly243 unique current IDs, current status-neutral core identities, unique closed-vocabulary approach tags and valid secondary topics excluding the primary. The independent approval binds the canonical normalized mapping hash, reviewer and timestamp. Missing, malformed, oversized, unapproved or stale metadata fails closed; no draft approval or silent review migration is accepted. QA source evidence remains outside runtime inputs. This additional gate is wired against the independently approved mapping; integrated helper/actual HTTP and full release audits pass. Final all243 HTTP/privacy and application acceptance remain separately recorded; the initial bank publication report precedes this addition.
